{#- The edit page's client half: round-to-leg chips, the cancelled toggle, and addRow() for both repeatable-row "+ Add" buttons. A round's leg chips are keyed by `day_key`, not by ConcertDay id, which is what lets a leg added in this session be assigned a round before it has ever been saved. A saved leg's key IS its id (the server renders it that way), so the two schemes are the same thing for every row that already exists -- the generated keys only ever describe rows the server has not seen yet. The hidden round_legs input stays the single source of truth for a row. Re-rendering rebuilds the BUTTONS from the day rows currently in the DOM and never touches that value, so a reference the chips cannot show (a cancelled leg) survives untouched -- and the toggle only ever adds or removes its own key. Delegated listeners, not inline onclick: leg names are user-controlled and the browser HTML-decodes an on* attribute before parsing it as JS, so Jinja's escaping would not protect an interpolated one (invariant 7). Client-built chips set .textContent for the same reason. -#}
