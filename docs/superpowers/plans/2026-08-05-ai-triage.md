# AI Triage of Discovery Leads (DeepSeek V4 Flash) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An admin button on `/admin/discoveries` that has DeepSeek classify the open discovery leads into a proposed prune list and draft the survivors into skeleton concert drafts (rounds always empty), landing on the existing prune-plan and pending-drafts review surfaces.

**Architecture:** The LLM emits the two text formats the app already parses — prune-list YAML (`parse_prune_list`) and the `add-concert` draft YAML (`parse_drafts`) — so validation happens at existing parser boundaries and review happens on existing surfaces. A `TriageRun` row is both the request stamp and the run record; the scheduler tick picks up requested rows (the `sweep_now` pattern), and the loop's failure handler marks the row failed on the cleaned transaction (the `stamp_discovery_run` two-halves pattern, in row form). Spec: `docs/superpowers/specs/2026-08-05-ai-triage-design.md`.

**Tech Stack:** Python 3.12, FastAPI, SQLAlchemy async + Alembic (SQLite), httpx (hand-rolled DeepSeek client, no SDK), pytest + pytest-asyncio.

## Global Constraints

- `uv run pytest -q` and `uv run ruff check .` MUST pass before every commit.
- The DB stores aware UTC only; `UTCDateTime` columns become `sa.DateTime()` in migrations; migrations use `batch_alter_table` where altering, `op.f()` names when creating.
- New migration chains from head `db750444962a`.
- No network in tests: `tests/conftest.py`'s `_no_real_network` raises on any `httpx.AsyncClient` built without a `transport` — every new HTTP call site MUST take a `transport` seam like `fetching.fetch_html` does.
- Admin surfaces are English-only, NOT wrapped in `_()` (like `/admin/deliveries`) — this build adds zero translatable strings, so the i18n catalogues are untouched.
- Notifications to admins go through the `notifications` outbox, never a direct DM (invariant 4). Kind `"triage"` is NOT added to `UNREPORTED_NOTE_KINDS` (it reports on a run, not on deliveries). The `ensure_user` guard is required before queueing (`if await session.get(User, admin_id) is None: await ensure_user(...)`).
- `import_commit` stays the only write path into `concerts`; drafts land only as `PendingDraft` rows; dismissals happen only via the existing plan screen.
- **Rounds are stripped in code** from every generated draft, whatever the model returned. This is the load-bearing safety property.
- Sequential third-party fetches with a 1s pause; beat the heartbeat inside the per-production loop.
- 303 redirects after admin POSTs, never 307.
- Config files stay ASCII-only.
- Branch: `ai-triage` (already created off origin/main).

### Task 4: `app/triage.py` — the runner

**Files:**
- Create: `src/app/triage.py`
- Test: `tests/test_triage_run.py` (runner half, same file as Task 1's service tests)

**Interfaces:**
- Consumes: `service.pending_draft_texts`, `service.open_leads` (verify the exact name/row shape in `db/service.py` — it is what `routes/discoveries.py:discoveries` renders; rows carry `source_event_id`, `title`, `event_date`, `venue`, `date_is_deadline`, `source`), `service.create_pending_drafts(session, batch, created_by)`, `parse_drafts`, everything from Task 2, `llm.chat` from Task 3, `fetch_html`/`FetchError` from `app.fetching`, `heartbeat` from `app.scheduler` (module import, bare `heartbeat.beat()` calls — the same shape `discovery.py:45` uses so tests can monkeypatch the attribute), `Notification`/`User`/`ensure_user` for the digest.
- Produces:
  - `@dataclass class TriageReport: leads_seen=0; productions=0; dismissals=0; drafts=0; skipped=0; calendar_skipped=0; tokens_in=0; tokens_out=0`
  - `async def run_triage(session, run: TriageRun, now: datetime, *, fetcher: Callable[[str], Awaitable[str]] = fetch_event_page, llm_chat = llm.chat) -> TriageReport`
  - `async def fetch_event_page(url: str, transport=None) -> str` — `fetch_html(url, allowed_host="www.eventernote.com", user_agent=TRIAGE_USER_AGENT, transport=transport)`; UA constant spelled out here in the style of `app/calendars.py` (which spells its own out to avoid an import cycle — copy that reasoning comment).
  - Constants: `TRIAGE_DRAFT_CAP = 25`, `TRIAGE_DELAY_SECONDS = 1.0`, `FETCH_DEADLINE_SECONDS = 30.0`, `EVENT_URL = "https://www.eventernote.com/events/{id}"`.

**Run order (module docstring carries the why, mirroring `discovery.py`'s top-of-file budget note):**
1. `rows = await open_leads(session)`; map to `LeadLine`s; `report.leads_seen = len(rows)`. Zero leads → mark the run done with zero counts and return (no LLM call).
2. Classify: `reply = await llm_chat(*classify_prompt(lines))`; accumulate tokens; `parse_classify_response(reply.text)` — a `TriageResponseError` here propagates (fails the run; the loop's handler marks it failed). Store `run.prune_yaml = result.prune_yaml`; `report.dismissals` = entry count via `parse_prune_list` when non-empty; `report.productions = len(result.survivors)`.
3. Containment: `taken = await pending_draft_texts(session)`; a survivor whose `EVENT_URL.format(id=representative)` occurs as a substring in any taken text is skipped (`report.skipped += 1`) — generated drafts embed exactly that URL (step 4), so a second press never re-drafts what is already waiting.
4. Draft loop over survivors, oldest-first as delivered, stopping after `TRIAGE_DRAFT_CAP` attempts: `representative is None` → `report.calendar_skipped += 1; continue` (nothing to fetch; the agent workflow keeps those). Else: `heartbeat.beat()` → `await asyncio.sleep(TRIAGE_DELAY_SECONDS)` → `async with asyncio.timeout(FETCH_DEADLINE_SECONDS): page = await fetcher(EVENT_URL.format(id=rep))` → `reply = await llm_chat(*draft_prompt(survivor, lines, page))` → `text = strip_rounds(extract_yaml(reply.text))` → prepend `f"# source: {EVENT_URL.format(id=rep)}\n"` → `batch = parse_drafts(text)`; require exactly one draft and no errors, else skip-and-count. `await create_pending_drafts(session, batch, created_by=run.requested_by)`; `report.drafts += 1`. EVERY per-survivor failure (fetch, LLM, parse) is `except Exception: log.exception(...); report.skipped += 1; continue` — one bad production must not cost the rest (the `run_sweep` philosophy).
5.
```python
        # AI triage runs only when an admin pressed the button: a requested
        # TriageRun row is both the request and the record. Its failure
        # handler is stamp_discovery_run's two-halves pattern in row form --
        # the rollback restores the row to "requested", so without the
        # re-mark on the cleaned transaction a dead run re-fires 25 fetches
        # and 26 LLM calls every 60 seconds forever.
        triage_run = None
        try:
            if settings.triage_enabled:
                triage_run = await pending_triage_run(session)
            if triage_run is not None:
                triage_report = await run_triage(session, triage_run, now)
                await session.commit()
                log.info(
                    "triage run %d: %d leads, %d dismissals proposed, %d drafts, %d skipped",
                    triage_run.id, triage_report.leads_seen, triage_report.dismissals,
                    triage_report.drafts, triage_report.skipped,
                )
        except Exception:
            log.exception("triage run failed; delivery was unaffected")
            await session.rollback()
            try:
                if triage_run is not None:
                    await mark_triage_failed(session, triage_run.id, now, "run failed; see logs")
                    await session.commit()
            except Exception:
                log.exception("triage: could not record the failed run")
                await session.rollback()
```
