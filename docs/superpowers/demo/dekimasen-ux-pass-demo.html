Part 2 — the aesthetic pass

Seven smaller judgements about the sheet as a whole. G1/G3/G5/G7 are mechanical; G2 and G4 are direction; G6 is a decision. Diffs in the spec, same ids.

G1

One weight ramp: 400 / 600 / 700

style.css

The sheet uses 400/500/550/600/650/660/680/700. On Windows, system-ui is Segoe UI, which has no intermediate grades — 550/650/680 snap to 600/700 there. The fine gradation only renders on macOS, so the design currently says two different things on two platforms. Consolidate to 400/600/700.

Current ramp vs proposed ramp

Current

Toggles and labels — 550

Section heads and card titles — 650

Hero promise — 680

Proposed

Toggles and labels — 600

Section heads and card titles — 700

Hero promise — 700

On Windows both columns render identically today; on macOS the right column is a hair heavier. That is the whole change.

G2

Two callout shapes, ten current one-offs

style.css

Ten hand-rolled “colored box” treatments have accreted (.callout, .banner-warn, .signin-note, .dupe, .upgradebox, .standing, .next, .feedbox, .danger-row, .danger). The grammar underneath is really two shapes: a status card (raise ground, left edge in the tone colour — the thing is ongoing) and a banner (wash ground, full border — the thing needs attention). Migrate the one-offs to tones of these.

The two shapes, three tones each
Shape 1 — status card (ongoing state)
Next for you — accent edge (.standing, .next, .upgradebox)
Payment due — danger edge (.feedbox becomes ok-edge, below)
Calendar feed ready — ok edge (.feedbox)
Shape 2 — banner (needs attention)
Sign in to continue — accent (.signin-note, .callout)
DM could not be delivered — off (.banner-warn, .dupe, .callout.warn)
Delete account — danger (.danger-row, .danger)

Migration map: status card ← .standing, .next, .upgradebox, .feedbox · banner ← .callout(+warn), .banner-warn, .signin-note, .dupe, .danger-row, .danger. Phased, visual-parity-first; detail in the spec.

G3

Write the radius system down

style.css header

3px base · 999px chips · 4px menus+dialogs · 50% dots · 14px bottom sheets is a real system, documented only in scattered comments. One block at the top of the sheet stops drift better than the test does.

Proposed comment block
/* ── Radius system ─────────────────────────────────────────────────
   3px              everything, by default (cards, inputs, buttons, pills)
   999px            chips and chip-like toggles (.chip, .tchip, .kindpick)
   4px              overlay CARDS only: .kmenu, dialogs (.prune)
   50%              dots, avatars, counters, ticks (circles, not radii)
   14px 14px 0 0    phone bottom sheets (dialogs + .fsheet panel)
   test_style_uses_3px_radius_not_6or8 guards the 3px default. */

G6

decided

The design's personality is restraint: the 150ms translateY(-1px) lift on hover, and nothing else moves. The F1 progress bar earns its place because it is functional. A1's breathing dot was the only decorative animation on the table — rejected (owner, 2026-07-24): the column-head colours carry “money at risk” alone. A1 ships without the dot.
